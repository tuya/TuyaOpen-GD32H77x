# VW553 minimum TCP/UDP AT extension candidate

> **历史补丁/验证记录，不是当前构建入口。**
> 当前 VW553 AT gateway canonical 构建入口见
> [`platform/GD32/gd32_os/MSDK/vw553_at_gateway/docs/README.md`](../../GD32/gd32_os/MSDK/vw553_at_gateway/docs/README.md)。
> 下文中的旧 SDK、overlay/staging、`/tmp` 路径和 `patch -p*` 命令只用于复现历史实验，不参与当前构建。

This patch targets the pinned GigaDevice SDK archive `GD32VW55x_RELEASE_V1.0.3g.zip` (SHA-256 `49995f9c482136e7b9be02fa4b1f1a6ea7716a215a0b993c1538a6d2f0792cea`) and expects the existing `docs/handoffs/gd32h77x-20261016/vw553-reference-config/` and `docs/handoffs/gd32h77x-20261016/vw553-overlay/` overlays to be applied first. The four affected `MSDK/app/atcmd*.c` and `.h` files must be normalized from CRLF to LF before applying the patch. A clean independent copy of the pinned ZIP was extracted, both overlays copied, line endings normalized, and `patch -p1 --dry-run` and apply both succeeded. It does not change BLE behavior or claim BLE capability.

The patch adds `AT+TY553XCAP?` and generic TCP/UDP listeners through `AT+TY553XSERVER=<TCP|UDP>,<port>`, query `AT+TY553XSERVER?`, and stop-by-type with port `0`. Legal listener ports are 1..65535. Legacy `AT+CIPSERVER` keeps its single-listener behavior and returns ERROR for every form while TY553XSERVER mode is active. TCP accepts emit `+TY553XCONN:<listener-fd>,<client-fd>,<peer-ip>,<peer-port>`; UDP payloads retain the vendor peer-address `+IPD` frame. CAP v1 responds `+TY553XCAP:1,ATOMIC_IPD,DUAL_SERVER,TCP_ACCEPT,UDP_SEND_ID=<MAX_CLIENT_NUM>,MAX_SEND=2048,MAX_CLIENTS=<MAX_CLIENT_NUM>`; numeric values are formatted from the compiled configuration. `MAX_CLIENTS` means ordinary connection ids are `0..MAX_CLIENTS-1`, while `UDP_SEND_ID` is the special `AT+CIPSEND` id for the UDP listener. With the default `MEMP_NUM_NETCONN=12`, the implementation reserves two listener and two local sockets, so `MAX_CLIENTS=8` and `UDP_SEND_ID=8`. A build with another `MEMP_NUM_NETCONN` reports its actual value.

Station power-save control is a separate extension. Apply
`vw553-speed-ps.patch` after CAP2 when the H77 TKL must be able to disable
VW553 traffic-based power save before WPA association; see
`vw553-speed-ps.md`. 

`vw553-ty553x-extension.patch` includes the existing atomic IPD TX lock and the dual-listener implementation. Apply it to the SDK work copy after the VW553 integration overlay with `patch -p1 < vw553-ty553x-extension.patch` from the SDK root. The listener worker publishes ready state only after local sockets and the receive buffer initialize; command success checks the listener slot after that handshake. Initialization failure and fatal `select()` errors share the cleanup path.

The candidate configured and compiled with the pinned `riscv-nuclei-elf-gcc` 10.2.0 toolchain, using the VW553 overlay's `app_cfg.h` with `CONFIG_ATCMD` enabled and no RF/signaling test macro: `MSDK.elf` linked at `/tmp/vw553-minimal-candidate/GD32VW55x_RELEASE_V1.0.3g/MSDK/projects/cmake/output/bin/MSDK.elf`. The build directory is `/tmp/vw553-minimal-candidate-build`; its CMake source root is the candidate tree above, and `MSDK/app/atcmd.c` includes `MSDK/app/atcmd_tcpip.c`. CMake's automatic post-build call passes the SDK root as argument 4, but `MSDK/projects/image_afterbuild.sh` requires argument 5; the MBL script separately requires the root as argument 2. The handoff's manual argument sequence was used to package into the candidate SDK copy's `scripts/images/image-all.bin`. `riscv-nuclei-elf-strings` confirms the `+TY553XCAP:...UDP_SEND_ID=%d,MAX_SEND=%d,MAX_CLIENTS=%d` format in the `atcmd.o`, `MSDK.elf`, `MSDK.bin`, and `image-all.bin`; `nm` shows `at_ty553x_cap` and `at_ty553x_server` in the ELF.

The packaged image is 1,098,524 bytes (within the 4 MiB flash capacity), begins with the exact 22,392-byte `MBL.bin`, has all-`0xFF` padding to `0xA000`, and has the exact 1,057,564-byte `MSDK.bin` at offset `0xA000`. ELF entry is `0x0800A1D0`, inside `.init` at `0x0800A000`; the vector's first instruction jumps to `_start`. `start.S` loads `sp` from `_sp`, whose linker value is `0x20048000`. Flash `.text` ends at `0x0810BE6C`, below the SDK's flash limit. Linker reports RAM 100% because its `.heap` and `.stack` sections are deliberately placed at the end of the entire `288K - RE_IMG_DATA_START` RAM region (`.heap` 2 KiB, `.stack` 2 KiB); it is a high-water region extent, not evidence that `.bss` itself fills RAM. `.data` is 1,200 bytes and `.bss` is 102,976 bytes, ending at `0x2001A9E8`, below the reserved top-of-RAM heap/stack. The temporary Python state model at `/tmp/test_vw553_server_model.py` passes four lifecycle scenarios; it is an invariant model, not execution of the production C functions. Production validation here is the cross-compile/link plus binary string/symbol inspection and source review; no runtime hardware test has been done. This stage does not implement a close URC, so the host cannot rely on a `+TY553XCLOSE` event for remote EOF. No device was flashed and no pinned archive or normal/recovery image was modified.
